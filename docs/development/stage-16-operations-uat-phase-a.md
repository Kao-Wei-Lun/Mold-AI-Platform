# Stage 16 Phase A — Demo Operations, Backup, Restore and Acceptance

Phase A turns the existing Stage 10–15 components into a consistent Windows operator workflow.
It intentionally does not claim the external Sites, ChatGPT workspace, paid OpenAI provider,
performance or final `1.0.0-demo` gates are complete.

## Unified commands

Run from the repository root:

```powershell
.\scripts\demo-start.ps1
.\scripts\demo-status.ps1
.\scripts\demo-status.ps1 -Json
.\scripts\demo-backup.ps1
.\scripts\demo-reset.ps1 -DryRun
.\scripts\demo-stop.ps1
.\scripts\demo-acceptance.ps1
```

For the normal local development stack, add `-LocalDevelopment` to status, backup, reset and
acceptance. `demo-start` is intentionally the private Sites Demo entry; `dev.ps1` remains the local
interactive startup command.

## Start and status

`demo-start.ps1` validates Windows, Docker Desktop, at least 10 GB free disk, the private runtime
environment, the stable Sites HTTPS origin and the merged Compose configuration before delegating
to the existing hardened Sites startup. `-ValidateOnly` performs no container changes.

`demo-status.ps1` is read-only. Text output is for operators and `-Json` is the canonical evidence
contract. It reports expected service state/images, API dependency readiness, all Demo dataset
counts, curated CAD reconciliation, Assistant provider health, MCP tool/deep-link/tunnel state and
the current Git commit/dirty state.

The JSON redaction contract is explicit:

```json
{
  "redaction": {
    "secrets_included": false,
    "urls_included": false,
    "tunnel_ids_included": false
  }
}
```

The status can be `degraded` while all core engineering capabilities are usable—for example, when
the deterministic Assistant fallback is selected or the Git worktree is dirty. Missing containers,
dependencies, curated reconciliation, MCP tools or required external paths produce `not_ready`.

## Backup contract

```powershell
.\scripts\demo-backup.ps1
.\scripts\demo-backup.ps1 -LocalDevelopment
.\scripts\demo-backup.ps1 -MetadataOnly
```

Backups are written below ignored `.runtime/backups` unless `-OutputRoot` is supplied. Every backup
contains:

- `postgres.dump`, using PostgreSQL custom format;
- `release-snapshot.json`, generated by the read-only canonical management command;
- artifact files unless `-MetadataOnly` was selected;
- `backup-manifest.json` with SHA-256 for the dump, snapshot and every artifact;
- Git source commit/branch/clean state, image inventory and the Qdrant rebuild policy.

Environment files, API keys, Demo bearer token, tunnel key and browser storage are never included.
Qdrant binary state is not authoritative; restore rebuilds it from canonical FeatureSets/chunks.

## Isolated restore drill

```powershell
.\scripts\demo-restore.ps1 `
  -BackupDirectory .runtime\backups\mold-ai-demo-YYYYMMDDTHHMMSSZ `
  -TargetProjectName mold-ai-verification-restore-drill `
  -CleanupAfterVerification
```

The target name must be bounded lowercase text ending in `-restore-drill`. The restore overlay
publishes no API, Web or MCP host port, so it cannot collide with or replace the active Demo. The
script rejects an existing target project, verifies every backup checksum, restores PostgreSQL and
artifact ownership, runs all canonical seeds, forces curated CAD Qdrant reindex, and requires a
strict dependency/reconciliation snapshot.

`-CleanupAfterVerification` removes only the exact isolated project and its volumes. It does not
accept filesystem deletion targets or operate on the active project.

## Operations reset

Preview only:

```powershell
.\scripts\demo-reset.ps1 -LocalDevelopment -DryRun
```

Execute after reviewing the preview:

```powershell
.\scripts\demo-reset.ps1 `
  -LocalDevelopment `
  -Confirmation "RESET OPERATIONS"
```

The default execution creates a full backup first. `-SkipBackup` is an explicit operator override
and prints a warning. Operations reset removes searches, comparisons, non-Golden reviews,
manual/smoke CAD, HMI source/export data, derived operation previews, related storage files and
Qdrant CAD points. It preserves:

- curated CAD source and preview lineage;
- canonical Knowledge, Process/Trial and CAE fixtures;
- Golden curated reviews and rule profiles;
- environment files, API keys and tunnel profiles;
- all existing Audit Events, plus a new reset audit event.

Only `operations` mode is exposed in Phase A. Dataset and full-volume modes remain blocked until
their separate double-confirmation and recovery tests are complete.

## Acceptance evidence

```powershell
.\scripts\demo-acceptance.ps1 -LocalDevelopment -AllowDirtyWorkingTree
```

By default it runs `test.ps1`, the appropriate running-stack smoke, a strict canonical release
snapshot and sanitized evidence generation below ignored `.runtime/evidence/demo-v1`. A local or
dirty development run can pass automated gates but is never labeled a release candidate.

The bundle records external Sites/ChatGPT and opt-in live OpenAI UAT as pending when they were not
actually executed. It never infers account/workspace readiness from local MCP health.

## Recovery guidance

- Failed backup: do not reset; inspect DB/container health and available disk.
- Checksum mismatch: quarantine the backup and create a new one—never bypass verification.
- Restore project already exists: choose a new bounded `-restore-drill` project name.
- Qdrant recovery: run `python manage.py seed_cad_demo --reindex` after Qdrant is healthy.
- Reset dry-run scope is unexpected: stop and review dataset IDs/source lineage before confirming.
- External path unavailable: keep local data intact; status remains `not_ready` until the tunnel or
  stable Sites entry is restored.

## Phase B release blockers

Phase B must still implement and verify dataset/full-volume reset, stale-job/fault recovery,
performance baselines, different-network Sites UAT, ChatGPT account/workspace MCP UAT, optional
paid-provider UAT, final evidence review and the `1.0.0-demo` release tag.
