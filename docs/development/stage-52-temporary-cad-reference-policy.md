# Stage 52 — 臨時 CAD 與正式相似度候選資料隔離

## 需求與使用流程

- 新上傳且尚未關聯的 CAD 僅供臨時分析。仍可保存選檔、切頁返回、旋轉預覽、抽取幾何、設計審查及發起相似度查詢。
- 不得作為其他相似度搜尋的候選資料，包括先前已上傳、已存在向量索引的未關聯檔案。
- 使用既有「關聯至模具版本」操作，建立 CAD → MoldRevision → Mold → Project 的真實外鍵關聯後，才可成為候選。
- 填寫檔名、資料集、產品類型或材料不等於關聯專案，也不能藉此取得候選資格。
- 本次不增加獨立的直接 Project 外鍵、不自動建立專案、不自動刪除檔案或操作紀錄、不新增有效期限。
- 對既有已關聯 CAD 新增版本時，繼承既有 Artifact 的歸屬，仍屬正式資料；若要獨立臨時分析，請使用新 CAD 上傳流程。

## 候選資格

每次搜尋以關聯式資料庫即時判定：

1. 已關聯模具版本；所屬專案與模具為 active，版本不是 archived。
2. CAD Artifact 為 active，並符合查詢的 classification。
3. FeatureSet 已索引，且 index_version 符合搜尋的固定版本。
4. 排除查詢本身及設定排除的資料集；既有使用者篩選／工程條件仍照常執行。

草稿模具版本的關聯仍算專案關聯，不新增「必須發布」的門檻；本次不改變既有存取權限。
此規則不以資料集名稱設例外。未關聯的公開 CAD 也不可混入線上候選池；離線評估直接比較特徵的流程不受影響。

## 實作與既有資料相容性

- 允許保留臨時檔的向量，供查詢、分析及日後歸檔使用；「已索引」不代表「正式候選」。
- V1、V2 線上搜尋共用 reference_features 判定。
- 粗搜尋前取得符合資格的 artifact_version_id，使用既有 Qdrant payload 欄位限定候選，再計算 top-k；防止大量臨時檔佔滿粗搜尋名額。
- 空集合不呼叫無篩選的向量搜尋，正常回傳零筆；不會降級混入臨時檔。
- 粗搜尋後再次套用資料庫條件，不信任過時的索引 payload 或僅依前端限制。
- 關聯完成後下一次搜尋即生效，不需重新解析／建立索引；封存後的新查詢排除該檔。
- 既有已完成搜尋結果是歷史快照，不回寫刪除；要套用新政策請重新送出搜尋。
- 無資料庫 migration、無大批資料或向量刪除。API 與 MCP 共用後端流程。

## UI

CAD 上傳區及相似搜尋區提供中英提示，說明「可作為查詢」與「可成為候選」的差別，以及檔案不會自動刪除。

## 驗證

- V1/V2：未關聯查詢可執行，未關聯候選不得回傳，即使索引仍回傳該 ID。
- V1/V2：粗搜尋的 ID 篩選排除臨時檔；關聯後不用重新索引即可納入，封存後排除。
- 只有臨時檔時回傳零筆，不呼叫無限制 Qdrant 查詢。
- 既有搜尋排序、工程條件、資源預算、模具關聯 API 回歸測試。
- 前端中英文政策提示、型別檢查、完整測試與正式建置。

## 限制與後續

Demo 使用資料庫計算候選 ID 清單，優先確保既有索引與關聯操作立即一致。大量企業資料時應改為具備交易事件／outbox 同步與對帳的索引資格欄位，避免每次傳送大型 ID 清單；仍保留後端資格覆核。
TTL、自助清理臨時檔及歷史結果即時資格標示為後續獨立需求，不在本次刪除任何使用者資料。
