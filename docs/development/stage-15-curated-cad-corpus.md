# Stage 15 — Curated CAD Corpus Operations

Stage 15 provides a governed, deterministic CAD corpus for demonstrations. It contains no company
or customer data and does not call an LLM API. The 16 normal fixtures are generated as ASCII STL
from versioned parameters. Two error controls verify an open shell and an invalid STL signature;
they are isolated from normal similarity candidates.

## Dataset contract

| Dataset | Purpose | Default catalog visibility |
|---|---|---:|
| `curated-cad-demo-v1` | Versioned Demo queries and candidates | Visible |
| `curated-cad-demo-errors-v1` | Expected invalid/degraded controls | Hidden by scoped use |
| `manual-cad-upload-v1` | Files uploaded in Web without an explicit dataset | Visible |
| `automated-cad-smoke-v1` | Disposable smoke-test CAD | Excluded |

The manifest is located at
`services/platform-api/platform_core/fixtures/cad/curated-demo-v1/manifest.json`. Its current
dataset version is `2026.08.1`. Every generated byte stream has a SHA-256 checksum. The CAD parse
Job input snapshot records fixture ID, role, scenario, rank group, dataset version, manifest hash,
generator and provenance. `ArtifactVersion.source_system` is `curated-cad-generator`.

These synthetic fixtures are demonstration and verification inputs, not engineering guidance.
Changing geometry, expected outcomes, labels, or generator behavior requires a new dataset version
and new fixture checksums.

## Seed and verification

From `services/platform-api` with the Python 3.12 virtual environment active:

```powershell
python manage.py seed_cad_demo
python manage.py seed_cad_demo --verify-only
```

The normal command performs the following gate:

1. Validates manifest schema, dataset ID, count, unique safe IDs/names and all checksums.
2. Creates missing Artifact, ArtifactVersion, CADModel and parse Job records through normal
   ingestion contracts.
3. Processes each fixture and verifies its bounding box and required quality flags.
4. Creates or repairs the deterministic FeatureSet and Qdrant index entry.
5. Reproduces both isolated error controls with their expected typed outcome.
6. Checks the SIM-A and SIM-B strong > usable > negative group ordering.
7. Runs four design-review scenarios and validates the rib/draft rule states.

The operation is idempotent. A second successful run reports `created=0`. If a FeatureSet is
missing, a normal run repairs it and increments `reconciled`; `--verify-only` never repairs data and
returns a non-zero command result when anything required is missing or inconsistent.

`python manage.py seed_demo_data` now includes this CAD gate in addition to Knowledge,
Process/Trial and CAE fixtures. Consequently, Qdrant must be available for a production-like seed.

## API and Web behavior

`GET /api/v1/demo/status` includes:

```json
{
  "demo_data": {
    "curated_cad": {
      "dataset_id": "curated-cad-demo-v1",
      "dataset_version": "2026.08.1",
      "expected": 16,
      "ready": 16,
      "indexed": 16,
      "reconciled": true,
      "golden_scenarios": {"similarity": 2, "design_review": 4}
    }
  }
}
```

Use `GET /api/v1/cad-artifacts?dataset_id=curated-cad-demo-v1` for the scoped catalog. Every item
contains a `source` object for trusted seeded provenance. Omitting `dataset_id` excludes automated
smoke CAD but can include curated and manual uploads.

In Web, click **Load curated Demo queries**, choose SIM-A or SIM-B, then click **Use as query**.
Loading the catalog alone does not emit an active query. Candidates, review reference fixtures and
error controls are never presented as curated queries.

## Golden invariants

- Both queries are excluded from their own candidate comparisons.
- Every strong candidate score is greater than every usable candidate score.
- Every usable candidate score is greater than every negative control score.
- Golden checks compare ranking groups rather than freezing floating-point scores.
- Review measurements are explicitly supplied Demo context. The UI and Assistant must not claim
  that rib thickness or draft angle was automatically measured from STL.
- Missing measurement context produces `NOT_EVALUATED`, never an inferred pass.

## Failure handling

- `Fixture checksum mismatch`: do not bypass it. Confirm whether the generator or manifest changed;
  intentional changes require a new dataset version and regenerated checksums.
- `geometry is not ready`: inspect the parse Job and parser error before retrying.
- `is not indexed`: restore Qdrant, then rerun the normal command. Do not use `--verify-only` to
  repair it.
- `rank invariant failed`: treat this as a profile/extractor regression and review the versioned
  Similarity changes before accepting new expected behavior.
- `golden review expected ...`: inspect the rule profile checksum and explicit context. Do not edit
  persisted findings to make the gate pass.
